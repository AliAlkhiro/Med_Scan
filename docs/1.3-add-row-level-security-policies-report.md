# 1.3 Add Row Level Security Policies Execution Report

Status: Done

## Summary

Added the Supabase Row Level Security baseline for the Med Scan MVP backend.

## Implemented

- Enabled RLS on `products`, `product_barcodes`, `attachments`, `usage_metrics`, and `admin_users`.
- Added authenticated admin policies for managing product records, barcodes, attachments, and admin users.
- Added authenticated admin read access for usage metrics.
- Added anonymous metric insertion for scan and attachment events without user, device, patient, or pharmacy identity.
- Added helper functions for admin checks and published product/attachment checks under RLS.
- Added a narrow public barcode lookup RPC that only returns published product details for a supplied barcode.
- Updated storage object policies to continue allowing reads only for files linked to published products after table RLS is enabled.
- Kept direct anonymous table access off product tables to avoid public product listing.

## Verification

- Reviewed the migration against `docs/design.md` security requirements and `docs/backlog.md` acceptance criteria.
- Confirmed the policy shape hides draft products from public lookup.
- Confirmed anonymous writes are limited to `usage_metrics` inserts.
- Confirmed storage policies use RLS-safe helper functions after RLS is enabled on product and attachment tables.

## Notes

- Public product reads should use `lookup_published_product_by_barcode(text)` rather than direct table queries.
- Admin bootstrap still requires creating the first `admin_users` row through a privileged Supabase path, such as the service role or SQL editor.
- Seed data remains part of backlog item 1.4.
