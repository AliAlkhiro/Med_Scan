# 3.3 Field-Test Scanner Behavior Execution Report

Status: Done

## Summary

Completed phone-based scanner testing and adjusted the pharmacist scanner flow based on test feedback.

## Field-Test Result

- Phone testing through an ngrok HTTPS tunnel confirmed that the pharmacist-side lookup flow is working.
- Continuous live scanning was unreliable: the scanner often stayed in a scanning state even when the barcode was visible.
- Manual photo-style scanning was a significant improvement for pharmacist-side testing.
- Additional crop and boundary-detection changes improved reliability when the barcode was visible but did not fill the whole guide box or orange guideline.

## Implemented

- Replaced continuous ZXing video decoding with a manual "Scan photo" action.
- Kept the live camera preview so pharmacists can align the product before scanning.
- Captured a still frame from the camera when the pharmacist taps the scan action.
- Added native browser `BarcodeDetector` support when available, allowing supported phone browsers to detect barcode boundaries inside the image.
- Kept ZXing as the fallback decoder for supported 1D MVP barcode formats.
- Corrected crop mapping between the visible CSS `object-cover` camera preview and the raw camera frame.
- Tried multiple decode candidates per scan:
  - visible guide box crop
  - horizontal bands inside the guide box
  - full camera frame
  - horizontal bands inside the full camera frame
- Preserved rear-camera preference, torch support, retry behavior, permission recovery, and duplicate navigation protection.

## Verification

- Ran `npm run build`.
- Ran `npm run lint`.
- User phone testing reported a major reliability improvement and confirmed pharmacist-side testing is going well.

## Notes

- 2D/Data Matrix support remains a future decision and was not added to MVP scope.
- Admin product creation is not available yet; it remains covered by Milestone 4.
